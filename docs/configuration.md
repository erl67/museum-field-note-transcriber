# Configuration and accounting

The CLI works from the checkout and resolves relative paths from the current directory. Global options go before the command. For example, `& $py -m fieldnotes --store local/collection --config local/config.json dry-run --input $scans`. Omit either option to use its default. Each store binds to one absolute input root on first inventory. Keep stores, outputs and the quota file outside that root. The only command intended to write beside scans is explicit managed publication.

Copy [the example configuration](config.example.json) into ignored `local/config.json` and edit the settings you need. It lists all defaults. Unknown keys and invalid values fail. The general installation uses [direct dependency pins](../requirements.txt). To reproduce the verified Windows Python 3.14.2 runtime, use `& $py -m pip install -r requirements-windows-py314.txt`. On an offline machine with a prepared wheel directory, use `& $py -m pip install --no-index --find-links 'C:\wheelhouse' -r requirements-windows-py314.txt`. [Full Windows runtime pins](../requirements-windows-py314.txt)

| Setting | Meaning |
| --- | --- |
| `model`, `temperature`, `thinking_level` | Explicit Gemini model and generation settings. Initial values are `gemini-3.5-flash-lite`, `1.0` and `high`. Model or setting rejection stops the batch with the provider's error. |
| `max_output_tokens` | Output budget. A truncated response retains its partial text and raw response. |
| `max_pages`, `max_request_bytes` | Whole-note preflight bounds. The byte estimate includes base64 expansion, prompt, page labels and serialization overhead. All pages travel together. |
| `max_edge`, `apply_orientation` | Longest submitted edge in pixels, or zero for original size. Orientation adjustment defaults to false. Requested resizing uses Lanczos and JPEG quality 95. Manifest entries identify original and submitted bytes and transformations. |
| `timeout`, `attempts` | Seconds per attempt (default 180, maximum 900) and total attempts per note (default 5, maximum 10). This budget includes at most one format correction. |
| `retry_base`, `max_retry_wait` | Transient-service retry delay starts at 60 seconds and doubles after each failed request, with up to 5 seconds of random jitter. The default five-attempt budget waits approximately 1, 2, 4 and 8 minutes. Each wait is capped at 600 seconds. A server-directed wait above that cap pauses the batch instead of being shortened. |
| `rpm`, `daily_limit`, `quota_timezone`, `quota_file` | Local pacing and persistent reservations. The day rolls over in the configured zone. Use one absolute field-note quota path across stores sharing this allocation. Keep the quota file when moving or resuming work. |
| `rates` | Defaults to null. Optional estimates need `model`, `currency`, `as_of` (date), `source` and nonnegative `input`, `cached`, `output` rates per million tokens. Obtain current rates for the actual model/account. |

Only `transcribe` reads credentials, after matching reusable work. It uses `GEMINI_API_KEY` or `GOOGLE_API_KEY` from the environment if set. Otherwise, it reads those assignments from `.env` in the current directory. Use `--env-file PATH` to select a specific credential file. Avoid pasting keys into commands, configs, reviews or reports.

The field-note defaults allow one attempt per minute and 500 per Pacific day, using the collection operator's specified daily allocation for `gemini-3.5-flash-lite`. Each whole card uses one initial attempt, even when both sides are scanned. Retries and format corrections each use another attempt. The field-note counter records attempts from stores using the same quota file. At either the local daily cap or a provider-reported daily limit, the batch stops. Run the same `transcribe --pending` selection after the daily reset, which defaults to midnight Pacific. Completed cards are skipped.

OS locks exclude concurrent store writers, and a separate quota lock protects reservations across field-note stores. If a process dies after reservation, the conservative reservation remains.

The pinned SDK uses the Gemini Developer API `v1beta` generate-content endpoint, ordered inline JPEG parts, a JSON response MIME type and a single SDK attempt. One application loop handles retry timing. Authentication/access failures, disabled or unavailable models/settings, billing and daily limits stop the batch. A transient failure may retry within bounds. A long server-directed wait pauses for later continuation. Account support, actual provider limits, cost and reading accuracy require an authorized run. [Python SDK](https://googleapis.github.io/python-genai/) · [Thinking controls](https://ai.google.dev/gemini-api/docs/thinking) · [Image input](https://ai.google.dev/gemini-api/docs/image-understanding)

HTTP 503 with a high-demand message is a service rejection, not evidence that the 180-second client timeout elapsed. The longer retry delays give temporary overload time to clear; they cannot guarantee availability. After five unsuccessful attempts ending in a transient error, the batch still stops with saved work intact. Each actual request counts toward the same daily 500-attempt limit; waiting consumes no attempts. The CLI reports the remaining wait at least once per minute. Ctrl+C during a retry wait saves the known failure; interruption during an in-flight request still requires explicit `--retry-interrupted` acknowledgment. An explicit configuration file keeps any values it overrides. [Google's retry guidance](https://aistudio.google.com/docs/troubleshooting#retry-strategy)

`usage --run latest` reports new attempts, known outcomes, and token totals for the latest started batch. Its separate `reused_history` section lists selected revisions and their historical token usage and cost estimates. Those figures do not enter the new run totals. Use a printed run ID to inspect an earlier batch. `usage` aggregates actual historical attempts once. The run-end event records how many results were reused. Reuse and offline regeneration add no service attempts. A provider total is recorded independently. Cached input is a subset of input, and reasoning is added to candidate output only when estimating billable output. Missing counters, pending outcomes or unavailable rates remain unknown. Each cost estimate carries its dated rate assumptions and currency. The provider invoice remains authoritative.

The `usage` fields remain null when any contributing attempt lacks that counter. The additional `reported_usage` fields show the known subtotal and the number of reported/missing attempts for each token category. Successful responses can omit cached-token counts, and service errors generally supply no counters. Neither omission is changed to zero. The CLI also prints a readable subtotal and explains missing cost estimates. These summaries can be calculated for earlier saved runs without resubmitting cards or rewriting history.
