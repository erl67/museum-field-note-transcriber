# Configuration and accounting

The CLI works from the checkout and resolves relative paths from the current directory. Global options go before the command. For example, `& $py -m fieldnotes --store local/collection --config local/config.json dry-run --input $scans`. Omit either option to use its default. Each store binds to one absolute input root on first inventory. Keep stores, outputs and the quota file outside that root. The only command intended to write beside scans is explicit managed publication.

Copy [the example configuration](config.example.json) into ignored `local/config.json` and edit the settings you need. It lists all defaults. Unknown keys and invalid values fail. The general installation uses [direct dependency pins](../requirements.txt). To reproduce the verified Windows Python 3.14.2 runtime, use `& $py -m pip install -r requirements-windows-py314.txt`. On an offline machine with a prepared wheel directory, use `& $py -m pip install --no-index --find-links 'C:\wheelhouse' -r requirements-windows-py314.txt`. [Full Windows runtime pins](../requirements-windows-py314.txt)

| Setting | Meaning |
| --- | --- |
| `model`, `temperature`, `thinking_level` | Explicit Gemini model and generation settings. Initial values are `gemini-3.5-flash-lite`, `1.0` and `high`. Model or setting rejection stops the batch with the provider's error. |
| `max_output_tokens` | Output budget. A truncated response retains its partial text and raw response. |
| `max_pages`, `max_request_bytes` | Whole-note preflight bounds. The byte estimate includes base64 expansion, prompt, page labels and serialization overhead. All pages travel together. |
| `max_edge`, `apply_orientation` | Longest submitted edge in pixels, or zero for original size. Orientation adjustment defaults to false. Requested resizing uses Lanczos and JPEG quality 95. Manifest entries identify original and submitted bytes and transformations. |
| `timeout`, `attempts`, `max_retry_wait` | Seconds per attempt (maximum 900), total attempts per note (maximum 10), and maximum acceptable server-directed wait. The default budget includes at most one format correction. |
| `rpm`, `daily_limit`, `quota_timezone`, `quota_file` | Local pacing and persistent reservations. The day rolls over in the configured zone. Use one absolute field-note quota path across stores sharing this allocation. Keep the quota file when moving or resuming work. |
| `rates` | Defaults to null. Optional estimates need `model`, `currency`, `as_of` (date), `source` and nonnegative `input`, `cached`, `output` rates per million tokens. Obtain current rates for the actual model/account. |

Only `transcribe` reads credentials, after matching reusable work. It uses `GEMINI_API_KEY` or `GOOGLE_API_KEY` from the environment if set. Otherwise, it reads those assignments from `.env` in the current directory. Use `--env-file PATH` to select a specific credential file. Avoid pasting keys into commands, configs, reviews or reports.

The field-note defaults allow one attempt per minute and 500 per Pacific day, using the collection operator's specified daily allocation for `gemini-3.5-flash-lite`. Each whole card uses one initial attempt, even when both sides are scanned. Retries and format corrections each use another attempt. The field-note counter records attempts from stores using the same quota file. At either the local daily cap or a provider-reported daily limit, the batch stops. Run the same `transcribe --pending` selection after the daily reset, which defaults to midnight Pacific. Completed cards are skipped.

OS locks exclude concurrent store writers, and a separate quota lock protects reservations across field-note stores. If a process dies after reservation, the conservative reservation remains.

The pinned SDK uses the Gemini Developer API `v1beta` generate-content endpoint, ordered inline JPEG parts, a JSON response MIME type and a single SDK attempt. One application loop handles retry timing. Authentication/access failures, disabled or unavailable models/settings, billing and daily limits stop the batch. A transient failure may retry within bounds. A long server-directed wait pauses for later continuation. Account support, actual provider limits, cost and reading accuracy require an authorized run. `usage --run latest` reports new attempts, known outcomes, and token totals for the latest started batch. Its separate `reused_history` section lists selected revisions and their historical token usage and cost estimates. Those figures do not enter the new run totals. Use a printed run ID to inspect an earlier batch. `usage` aggregates actual historical attempts once. The run-end event records how many results were reused. Reuse and offline regeneration add no service attempts. A provider total is recorded independently. Cached input is a subset of input, and reasoning is added to candidate output only when estimating billable output. Missing counters, pending outcomes or unavailable rates remain unknown. Each cost estimate carries its dated rate assumptions and currency. The provider invoice remains authoritative.
